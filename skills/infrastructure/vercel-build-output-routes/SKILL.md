# vercel-build-output-routes

Vercel's routing table (`.vercel/output/config.json`) is generated by the
platform's framework builder **after** your buildCommand finishes, so no build
script can patch it. The reliable injection point is the legacy `routes` array
in `vercel.json`, which the builder merges into the final routing table with
phase markers (`handle: filesystem` etc.) respected. This skill captures when
each path works, why the obvious ones fail, and how to verify placement
locally before deploying.

## When to use

- You want requests (e.g. missing static assets) to be answered at the edge
  routing layer without invoking a serverless function.
- Your project uses a framework preset that emits Build Output via the
  platform builder (`@vercel/react-router`, `@vercel/remix`, ...), so you do
  not own `config.json`.
- Not needed for Next.js asset 404s (its builder already short-circuits
  `/_next/static` misses) or for projects deploying a hand-written Build
  Output API directory (just edit your own `config.json`).

## Why the obvious approaches fail

```text
buildCommand:  pnpm build && node patch.mjs
               └─ runs first ──► platform builder runs AFTER ──► config.json
                  patch.mjs finds nothing to patch → build fails or no-ops

buildCommand:  vercel build && node patch.mjs
               └─ `vercel build` re-reads project buildCommand → infinite recursion

react-router.config.ts buildEnd:
               preset buildEnd and user buildEnd run via Promise.all —
               concurrent, unordered; you cannot sequence after the preset.
               (The preset's buildEnd only writes an intermediate
               .vercel/react-router-build-result.json anyway, not config.json.)
```

## Workflow

```text
[1] Check vercel.json compatibility (`routes` is exclusive with modern keys)
[2] Add legacy `routes` array with phase marker + rule
[3] Verify locally: `vercel build` → inspect .vercel/output/config.json
[4] Push / deploy
[5] Verify live with curl (rule fires, static files intact, SSR intact)
```

### [1] Compatibility check

`routes` cannot coexist with `rewrites`, `redirects`, `headers`, `cleanUrls`,
or `trailingSlash` in `vercel.json` — the platform rejects the combination.
If those keys are in use, see Fallbacks below.

### [2] Add the routes

Example — 404 missing `/assets/*` at the routing layer:

```json
{
  "routes": [
    { "handle": "filesystem" },
    { "src": "^/assets/.+", "status": 404 }
  ]
}
```

Semantics: `{ "handle": "filesystem" }` is a phase marker, not a route. Rules
after it apply only when no static file matched. User rules are merged at the
top of their phase, **ahead of** the builder's own rules (the SSR catch-all
`{"src": "/(.*)", "dest": "*"}` style rewrites), so your rule wins without
touching them. `src` is PCRE; a `status` rule with no `dest` returns an empty
body at the edge — zero function invocation.

Optionally add `"headers": { "cache-control": "public, max-age=300" }` to the
404 rule if your CDN should absorb repeats — but beware caching 404s for
asset URLs still referenced by older deployments (skew).

### [3] Verify locally before deploying

```bash
vercel build   # produces .vercel/output/config.json with the merge applied
python3 -c "
import json
rs = json.load(open('.vercel/output/config.json'))['routes']
for i, r in enumerate(rs):
    if r.get('handle') or 'assets' in json.dumps(r): print(i, json.dumps(r)[:120])
"
```

Expected shape: your rule sits immediately after `{"handle": "filesystem"}`
and before the builder's rewrites/catch-all. If the CLI errors about
conflicting config keys, you hit the [1] exclusivity rule.

### [5] Verify live

```bash
curl -sI https://<domain>/assets/nonexistent-deadbeef.js
# → 404, x-vercel-error: NOT_FOUND, content-type: text/plain  (edge, no function)

curl -sI -A "Mozilla/5.0 ..." https://<domain>/assets/<real-file>.js
# → 200 with the original immutable cache-control      (filesystem untouched)

curl -sI https://<domain>/some-nonexistent-page
# → SSR-rendered 404 HTML                              (catch-all untouched)
```

Routing-layer 404s carry `x-vercel-error: NOT_FOUND` and a tiny text/plain
body; SSR 404s carry your app's HTML content-type and cache headers. That
header difference is the proof the function was bypassed.

## Fallbacks when `routes` is unavailable

- **Prebuilt deploys from CI**: `vercel build && node patch.mjs && vercel
  deploy --prebuilt`. Full control over config.json; costs you the git
  integration's automatic deployments. This is the only recursion-free way to
  run a patch script, because CI's `vercel build` executes the real
  buildCommand as a child, not itself.
- **Migrate modern keys into `routes`**: `@vercel/routing-utils`'s
  `getTransformedRoutes` converts `rewrites`/`redirects`/`headers` syntax to
  legacy route objects, letting you consolidate everything under `routes`.

## Common pitfalls

| Mistake | Fix |
| ------- | --- |
| Patching `.vercel/output/config.json` from buildCommand or a `postbuild` script | It does not exist yet on the platform; builder runs after buildCommand. Use `vercel.json` `routes`. |
| `vercel build` inside the project's buildCommand | Recurses (platform's `vercel build` re-invokes buildCommand). Only run `vercel build` from external CI. |
| Sequencing after the framework preset via `buildEnd` in react-router.config.ts | Preset and user `buildEnd` run under `Promise.all` — concurrent, no ordering guarantee. |
| Adding `routes` while `rewrites`/`headers`/`redirects`/`cleanUrls`/`trailingSlash` exist | Mutually exclusive; deployment fails validation. Consolidate via `getTransformedRoutes` or use prebuilt CI deploys. |
| Forgetting `{ "handle": "filesystem" }` before a 404 rule | The rule then runs in the main phase and 404s *real* static files too. |
| Verifying only on the deployed URL | `vercel build` locally and inspect config.json first — the merge result is fully deterministic. |
| Testing the live site with plain `curl` when the app has AI-agent UA redirects | Send a browser `User-Agent` or you measure the redirect, not the route. |
| Caching the asset 404 aggressively at the CDN | Older deployments' asset URLs would be pinned to 404 during rollouts (version skew). Keep TTL short or none. |

## Verification

- [ ] `vercel.json` has no keys conflicting with `routes`.
- [ ] Local `vercel build` shows the rule directly after the intended phase
      marker and before the builder's catch-all.
- [ ] Live: missing-asset URL → 404 with `x-vercel-error: NOT_FOUND`.
- [ ] Live: real asset → 200 with original cache headers.
- [ ] Live: non-asset 404 page still SSR-rendered.
